# НОВИЧОК — первые 90 дней

Прототип продукта для сети спортивных товаров (~400 человек). Это не HR-портал и не LMS,
а тонкий риск-радар поверх Битрикс24: он показывает, кого из новичков нужно спасти сегодня,
и превращает сигнал в конкретное действие с дедлайном.

Главный пользователь — HR-партнёр и руководитель магазина/склада. Главный сценарий —
утренний разбор красной зоны за 2–3 минуты вместо ручного обзвона и выгрузок.

## Что внутри

- **Пульс** — KPI, красная зона, фокус-карточка новичка, лента событий, ближайшие чек-ины.
- **Новички** — таблица всех 14 человек, поиск, фильтры по риску, добавление новичка.
- **Аналитика** — удержание по дням, причины ухода, прозрачная расшифровка весов риска.
- **Карточка новичка** — сигналы с баллами, наставник, задачи, чек-ины, 1:1.
- **Действия** — назначить наставника, провести чек-ин, создать задачу в «Битрикс24».

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`.

Проверки:

```bash
npm test        # 16 unit-тестов
npm run build   # tsc --noEmit + production-сборка
npm run preview # локальный просмотр собранной версии
```

## Демо-сценарий (2 минуты)

1. На главной найдите **Марину Ковалёву**: день 12, риск **94**, нет наставника,
   две просроченные обязательные задачи, пропущен чек-ин на 7-й день.
2. Нажмите **«Разобрать»**.
3. Назначьте наставника **Светлану Романову** → риск становится **72**.
4. Проведите чек-ин, выберите настроение **«3 — нормально»**, добавьте блокер →
   риск становится **48**, карточка уходит из красной зоны.
5. Закройте карточку: на дашборде красных было **3**, осталось **2**.
6. Создайте задачу руководителю — появится тост с номером задачи в «Битрикс24».
7. Сбросьте демо в сайдбаре, чтобы вернуть исходные данные.

## Риск-модель

Правила намеренно простые и объяснимые: каждому сигналу соответствует строка в карточке.

| Сигнал | Баллы |
| --- | ---: |
| Пропущен чек-ин | +24 |
| Не назначен наставник (с 3-го дня) | +22 |
| Низкая оценка на чек-ине (1–2 из 5) | +20 |
| Просрочена обязательная задача | +18 за задачу, максимум +36 |
| Наставник недоступен (уволился) | +16 |
| Нет 1:1 с руководителем более 14 дней (после 21-го дня) | +14 |
| Не закрыта первая неделя (после 7-го дня) | +12 |
| Наставник не встречался 14+ дней (после 14-го дня) | +10 |

Красная зона — **50+**, жёлтая — **25–49**, зелёная — **0–24**. Это гипотеза для демо,
а не откалиброванная на реальных данных модель.

## Данные

- 14 синтетических новичков, 191 задача, 56 чек-инов, 7 наставников.
- Все имена, магазины, склады и события вымышлены; совпадения случайны.
- Даты старта задаются относительно «сегодня», поэтому демо не устаревает.
- Состояние хранится в `localStorage` (`novichok-90-demo-v1`), кнопка сброса — в сайдбаре.
- «Битрикс24» — **демо-адаптер**: задачи получают локальные номера, события пишутся
  в ленту, никакие данные никуда не отправляются.

## Ограничения

- Нет реальной интеграции с Битрикс24: OAuth, вебхуки и синхронизация не реализованы.
- Нет бэкенда, авторизации и ролей: всё работает в одном браузере.
- Веса риска и пороги — демо-гипотеза, требуют калибровки на реальных данных.
- Нет LMS, библиотеки контента, чата и мобильного приложения — сознательно.
- Проверено в Chrome; другие браузеры и доступность отдельно не тестировались.
